## 1. كيف تمت المراجعة

المراجعة كلها مبنية على تشغيل فعلي وقياس، لا على قراءة الكود وحدها.

| المحور | ما جرى | النتيجة |
| --- | --- | --- |
| الصلاحيات | دخول بأربعة أدوار (مدير، مشغّل، منفذان) وزائر، ثم 19 نقطة API لكل دور، ومقارنة النتيجة بالمتوقع | **19/19 صحيحة**، مع ملاحظة واحدة (L1) |
| الجلسات والدخول | حساسية الأحرف، الخطأ الموحد، تدوير refresh، الخروج، أصل غير موثوق، تعطيل حساب نشط | **كلها صحيحة** |
| لوحة التحكم | كل شاشة لكل دور، على الهاتف (iPhone 13) والكمبيوتر (1440px)، مع درج الطلب؛ تسجيل أخطاء المتصفح والطلبات الفاشلة والتمرير الأفقي | **46 زيارة شاشة، صفر طلبات فاشلة، صفر تمرير أفقي** |
| الموقع العام | 12 صفحة وحالة (منها 404 وطلب غير موجود) على 4 مقاسات: 390 و768 و1440 و1920 | **48 تحميلًا، رموز HTTP صحيحة، صفر تمرير أفقي** |
| الاختبارات الآلية | Django (151) وPlaywright (34، منها axe لكل صفحة وشاشة) | **كلها ناجحة** |
| التصميم | لقطات كاملة لكل ما سبق ومراجعتها مقابل ممارسات UI/UX الحديثة | الملاحظات في الأقسام 3 إلى 5 |

حسابات المراجعة أُنشئت محليًا فقط (`review-operator` و`review-exec1` و`review-exec2`) بكلمات مرور عشوائية، ولا تذهب إلى الإنتاج.

## 2. ما يعمل جيدًا (لا يحتاج تغييرًا)

- الدور يُقرأ من قاعدة البيانات في كل طلب؛ تعطيل الحساب يقطع جلسته النشطة فورًا (تحقق فعلي: 200 ثم 401).
- المنفذ لا يرى إلا الطلبات المسندة إليه، حتى بطلب المعرّف مباشرة (404 لغيرها).
- `refresh` يُدوَّر ويُبطَل عند الاستعمال والخروج؛ إعادة استعمال الرمز القديم تفشل.
- الدخول برسالة وزمن موحدين للمستخدم المجهول وكلمة المرور الخاطئة؛ أصل غير موثوق يُرفض (403).
- لا يوجد open redirect في صفحة الدخول.
- التنزيل بروابط موقّعة قصيرة العمر؛ الصفحات الخاصة محجوبة عن محركات البحث.
- الموقع العام بعد #19 و#20: تنقل تطبيقي على الهاتف، سلم خطوط، حقول 16px، وصولية AA بلا مخالفات.

## 3. المنطق والأمان

| # | الأولوية | الملاحظة | الدليل | الإصلاح |
| --- | --- | --- | --- | --- |
| **L1** | متوسطة | **المنفذ يرى عروض الأسعار والدفعات** (المبلغ والعملة والملاحظة) في الطلبات المسندة إليه، مع أن القاعدة «الأسعار والدفع للمدير والمشغّل فقط». لا يستطيع التعديل (403) لكنه يقرأ | API: عرض 15,000 SDG ظاهر للمنفذ؛ والواجهة تعرض له تبويب «السعر والدفع» | إخفاء `quotes` و`payments` و`payment_status` من الـ serializer للمنفذ، وإخفاء التبويب، مع اختبار |
| **L2** | منخفضة | `?next=` يُتجاهَل بعد الدخول: من يفتح رابط طلب وهو خارج الجلسة يصل إلى «نظرة عامة» لا إلى الطلب | قراءة الكود | احترام `next` إن كان مسارًا داخليًا يبدأ بـ `/admin` فقط (رفض `//` والمخططات)، مع اختبار |
| **L3** | متوسطة | **لا يوجد `global-error.tsx`**: إن فشل جلب الإعدادات في تخطيط الموقع تظهر صفحة خطأ Next الإنجليزية الافتراضية | الملف غير موجود؛ `(site)/error.tsx` لا يلتقط أخطاء التخطيط نفسه | صفحة خطأ عربية عامة بزر «إعادة المحاولة» |
| **L4** | منخفضة | حقول لوحة التحكم (بحث الطلبات والرسائل، الإنشاء السريع، ملاحظة الطلب، قوائم التصفية) بحجم 12px، فيكبّر iPhone الصفحة عند لمسها | قياس CSS | 16px على الهاتف |
| **L5** | منخفضة | صفحة النجاح تعرض أي رقم في الرابط دون تحقق | قراءة الكود | لا بيانات تتسرب؛ يكفي التحويل إلى الرئيسية إن غاب الرقم |
| **L6** | منخفضة | صفحة الدخول تطلب refresh عند فتحها فيظهر 401 في وحدة التحكم لكل زائر | الزحف | علامة جلسة غير حساسة (كوكي عادي «يوجد جلسة») لتخطي الطلب حين لا جلسة |

كل حركة CSS أو بلا مكتبة، وتتوقف مع «تقليل الحركة»، ولا تحرك عنصر LCP.

## 8. قبل الإطلاق (قرارات المالك)

- **نصا الخصوصية والشروط ما زالا مبدئيين** («نص مبدئي يحتاج مراجعتك» في صفحة «الصفحات»): يجب مراجعتهما قانونيًا قبل النشر.
- تغيير كلمة مرور تطبيق Gmail وكلمة المرور `0099` قبل الإنتاج.
- بيانات الاختبار المحلية (حسابات المراجعة، `e2e-admin`، الطلبات التجريبية) محلية فقط؛ قاعدة الإنتاج تبدأ نظيفة.

## 9. خطة التنفيذ

خمس دفعات، كل دفعة طلب دمج مستقل، يُختبر ويُراجع قبل التالية. الترتيب حسب الأثر: الأمان أولًا، ثم ما يعيق الاستعمال على الهاتف، ثم التحسينات.

### الدفعة A: المنطق والأمان (صغيرة، أولًا)
- **L1** إخفاء المال عن المنفذ (API + الواجهة) مع اختبار Django واختبار Playwright.
- **L2** احترام `next` الداخلي بعد الدخول، مع اختبار ضد `//evil` و`https://`.
- **L3** `global-error.tsx` عربي بزر إعادة المحاولة.
- **P1** صفحة 404 داخل إطار الموقع.
- **L4** حقول لوحة التحكم 16px على الهاتف.
- **L5 / L6** صفحة النجاح بلا رقم، وتخطي refresh عند عدم وجود جلسة.

**القبول:** مصفوفة الصلاحيات 19/19 مع فحص جديد «المنفذ لا يرى المال»، وكل الاختبارات الحالية ناجحة.

### الدفعة B: لوحة التحكم على الهاتف
- **D1** رأس صفحة مدمج.
- **D2** الجداول بطاقات تحت 760px.
- **D3** مرشحات الطلبات في لوحة سفلية مع شرائح نشطة.
- **D4** سلم الخطوط للوحة التحكم.
- **D10** «طلباتي» صفحة المنفذ الأولى.

**القبول:** لقطات قبل وبعد لكل شاشة على الهاتف والكمبيوتر، وصفر تمرير أفقي، وaxe بلا مخالفات، وأول طلب يظهر في الشاشة الأولى على الهاتف.

### الدفعة C: لوحة التحكم كتجربة
- **D5** الإعدادات: أقسام وشريط حفظ ثابت وتنبيه المغادرة.
- **D6** «يحتاج انتباهك» ومؤشر الأيام السبعة.
- **D7** الفريق: الأعضاء أولًا.
- **D8** محرر القائمة المدمج.
- **D9 / M4** هياكل التحميل وحركة الإشعار.

**القبول:** اختبارات Playwright لتنبيه المغادرة دون حفظ ولإعادة ترتيب القائمة، ولقطات قبل وبعد.

### الدفعة D: الموقع العام والحركة
- **P2** زر «اطلب الخدمة» الثابت على الهاتف.
- **P3** بطاقة معلومات التواصل.
- **P4** الشاشات الكبيرة.
- **M1 / M2 / M3 / M5** الحركة.

**القبول:** تصوير الحركات إطارًا بإطار كما في المراجعة، وعدم تغير CLS (يبقى 0)، وتوقف كل حركة مع «تقليل الحركة».

### الدفعة E: الأداء
- **PF1** فصل CSS لوحة التحكم.
- **PF2** قياس وتحليل ثم إصلاح المهام الطويلة.

**القبول:** Lighthouse في CI يسجل LCP ≤ 2.5s وTBT ≤ 200ms في الصفحات الثلاث، وحجم CSS الموقع العام مسجل قبل وبعد.

كل دفعة تُحدِّث `docs/test-report.md` و`docs/decisions.md`.
